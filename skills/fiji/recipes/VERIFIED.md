# Verified recipe runs

Every recipe in this folder was run on 17 Oct 2026 against the installed Fiji (2.18.0 / ImageJ 1.54p, `.local/fiji/Fiji.app`) in a windowless batch session that never touches the interactive instance on port 49557:

```
.local/fiji/Fiji.app/Fiji.app/Contents/MacOS/fiji-macos-arm64 -Dapple.awt.UIElement=true -Dij.batch=true -batch <case.ijm>
```

`-Dij.batch=true` keeps the Luma bridge from auto-starting; `-batch` runs ImageJ in batch mode (no windows, no Dock icon), the same mode the recipes switch on internally with `setBatchMode(true)`. Each case macro opens the sample from `.local/data/samples` (MANIFEST.json there), applies the setup listed, then calls `runMacro(<recipe>.ijm, <argument>)` — the same code and `getArgument()` string that `fiji_run_recipe` sends to the bridge's `run_macro` (`IJ.runMacro(code, argument)`). "ms" is the recipe's own run time inside Fiji (Fiji start-up, about 2 s, excluded). Synthetic cases build an image with known ground truth in the case macro first; they are what proves a recipe correct, the real samples prove it runs on real data. Numbers are software outputs for these settings on these images, not biological ground truth: say the settings with a result.

Not verifiable in a batch session (verified only by code review, not by a run): the ROI Manager path of `nearest-neighbour` (in batch mode each nested macro has its own hidden ROI Manager, so the run used a point selection), the windows the recipes show when they end outside batch mode (`setBatchMode("exit and display")`, `Plot Profile`, the TrackMate track overlay, which is only drawn when the image has a window), and anything that needs the bridge's 20 s `run_macro` wait to be longer (Coloc 2 with 10 Costes randomisations took 11 s on a 672×512 image; larger images or more randomisations may come back as `running`, and the RESULT line then appears in the Log).

## Plugin behaviour found while verifying (why some recipes call plugin APIs)

- **Analyze Skeleton** and **Directionality** do not show their summary tables in batch mode, so `skeleton-network` and `directionality` read the plugins' own result objects (`AnalyzeSkeleton_.run(...)`, `Directionality_.getFitAnalysis()`) through `eval("js", …)`; the numbers are the plugins' own.
- **Coloc 2** fails under `--headless` (its dialog has no checkboxes there) and, in a window session, shows its numbers only in a separate result window. `coloc2` runs Coloc 2's own `initializeSettings`/`colocalise` (the code path of the menu command) and prints the full report to the Log; `java.awt.headless` reads true only while it runs, so no extra window opens.
- **Linear Stack Alignment with SIFT** and **Pairwise stitching** report transformations only through `IJ.log`, which goes to the console when there is no Log window; `drift-correction` and `pairwise-stitch` read the Log and the console.
- **Bleach Correction** and **Kuwahara Filter** refuse 32-bit images; **Anisotropic Diffusion 2D** refuses 32-bit; **Gray Morphology** needs 8-bit (the spot top-hat uses ImageJ's own *Top Hat…* instead).
- In ImageJ macro, `x = pennyParam("flag", "true") == "true";` is a syntax error ("Numeric return value expected"); recipes assign the text first and compare on the next statement.
- Subtracting the DAB mask from the haematoxylin mask leaves the unstained rim of a positive nucleus behind, so `dab-positive-area` segments nuclei once from the combined mask and classifies each whole nucleus by its DAB share.
- `getStatistics(area, …)` returns the calibrated area, not a pixel count; recipes that need pixel counts use `getRawStatistics`.
- Auto Local Threshold's Phansalkar/Sauvola mark flat bright background as object (their threshold is a fraction of the local mean); `local-threshold` defaults to Mean with an offset, which counted all 16 discs on the shaded test image where Phansalkar found 9.

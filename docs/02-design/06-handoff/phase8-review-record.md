# Part B — Lead fix decisions

# Lead decisions for applying the Phase 8 review (REVIEW.md)

These resolve each finding that needed a design choice. Apply them consistently in **every** affected document. Mark each resolution in the touched document's change log as "Phase 8 review fix (finding #n)".

## High

**H1 — ROI store (finding 1).** **Canonical design = D04 §4.**
- The engine owns per-document ordered sets of `Roi` objects.
- There is ONE singleton `RoiManager`, created with `new RoiManager()` and hidden immediately. Hiding is window policy P-A.
- Before any action flagged `uses_roi_manager`, the document's set is loaded into the singleton. After the action it is read back.
- `RoiManager(boolean)` hidden managers are NOT used as the store. They are never the singleton, so commands and macros cannot see them (`RoiManager.java#L105-L112`, `#L2081-L2086`).
- Nuance to state: `getInstance()` returns the batch-mode manager only when no singleton exists. Our singleton therefore takes precedence, even inside macros.

Fix every place that says a hidden `RoiManager(false)` or `(true)` is the per-document store: D01 CMP-30, D13, D14, A21, A18, D05 if present, and FR-ROI-004 wording in A26. In the analysis documents (A15 CR-A15-04, A18), do not rewrite the evidence. Append a note: "Superseded in design by D04 §4 (singleton load/read-back); see Phase 8 finding 1."

In A26, change **FR-ROI-004 priority to MVP**, because J-12 needs it (finding 14). Update its statement so it says "backed by the engine-owned ROI sets and the hidden singleton `RoiManager` (D04 §4)".

D20's "state ownership unambiguous" may stay Satisfied once the fix is applied, with the note "after Phase 8 fix".

**H2 — Dialog-entered values (finding 2).** Replace the claim that a `CommandListener`/`Macro.getOptions()` captures values typed into a surfaced dialog. The listener fires before the dialog opens (`Executer.java#L54-L61`), and empty options clear the thread entry (`Macro.java#L97-L103`). New design:

- Primary (**PROPOSED, validation item V-10**): while `WAITING_FOR_DIALOG`, the dialog watch keeps an up-to-date snapshot of the open `GenericDialog`'s field values. P83 shows the fields are readable from code. On OK, the last snapshot is mapped to macro keys with `Macro.trimKey` applied to the labels, and recorded with provenance `dialog-snapshot`.
- Fallback when V-10 fails or the dialog is not a `GenericDialog`: record the step as "parameters entered in a Fiji dialog — not captured" (provenance PARTIAL). E7 replay is then flagged non-reproducible for that step.
- Additional mitigation: grow schema coverage so that product commands never show dialogs.

Apply this to D04 §7, D09 (the dialog sequence and `ObservedAction`), D10 §1/§4, D17 and D16 wherever the claim appears. Add V-10 to D04 §10 and D20 §6.

**H3 — Start-up order (finding 3).** New order in D03 §3:
1. The JVM starts. The Fiji/Jaunch splash screen covers this phase (VERIFIED: `fiji.toml#L254-L255` sets the splash image unless `--no-splash`).
2. The Context is created and the legacy layer initialises.
3. **`UIService.showUI(product UI)` is called immediately.** UI-19 shows the INITIALISING state.
4. The engine service completes its self-test and listener and hook registration, then **builds the catalogue asynchronously**, emitting `BUILDING_CATALOGUE`.
5. `READY`.

The engine states the UI can display are therefore INITIALISING, BUILDING_CATALOGUE, READY, FAILED and QUITTING. The STARTING phase is covered by the splash screen, not by UI-19. Update D03's sequence diagram and state list, D09 `EngineStateChanged` (add QUITTING), D14, D15 and D16 PC-2 consistently. FR-SYS-006 stays satisfiable.

**H4 — Rendering and locking (finding 4).** Remove the "render proxy + `lockSilently()`" design (D13 DP-D13-01). New design, **PROPOSED, V-11**:
- Rendered planes are produced **on the engine worker between actions**, never concurrently with a running command. The worker renders the visible planes as an internal post-action step when the digest marks them changed, plus on-demand render requests queued as AC0 internal tasks.
- The UI draws only cached ARGB copies (NFR-PERF-004).
- While an operation runs, the UI shows the last cache (D09 SY-2).
- No product code takes `ImagePlus` locks for rendering.

Also:
- Before R1 execution, the engine checks `imp.isLocked()`. If the image is locked, the action fails with `PRECONDITION_FAILED` ("image locked by another operation") instead of silently not running.
- D06 `IN_PLACE_PIXELS`: a "legitimate no-op" is accepted only when the command's schema flag `mayBeNoOp=true` is set. Otherwise an unchanged hash means `POSTCONDITION_FAILED`.
- **Overlays:** `getBufferedImage` excludes overlays (`ImagePlus.java#L606-L611`). The viewer draws overlays and ROIs itself from engine-supplied geometry (D13 conventions). Correct D09 L84, ADR-009, A21 and D04 R3 wherever they say rendering "includes overlays".

Add V-11 (render-on-worker latency) to D04 §10 and D20 §6.

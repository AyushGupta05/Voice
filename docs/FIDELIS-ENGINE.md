# Fidelis engine: architecture invariants and contract reference

The Fidelis workstation (`fidelis-app/`) runs the real Fiji in one persistent JVM behind a modern Swing/FlatLaf
workspace. Everything that changes an image goes through one engine (`sc.fidelis.engine`), whose typed contract is the
package `sc.fidelis.engine.api`. **The implemented code is authoritative**: this page summarises it so that nobody needs
to re-derive it, and when the two disagree the code wins and this page is corrected. Penny's bridge over this engine is
specified in [FIDELIS-PROTOCOL.md](FIDELIS-PROTOCOL.md); how the pieces fit together is in [INTEGRATION.md](INTEGRATION.md);
the numbers behind the parity claims are in [FIDELIS-VERIFICATION.md](FIDELIS-VERIFICATION.md).

## 1. Architecture invariants (do not break)

Hybrid B, as implemented:

- One persistent, **non-headless** Fiji JVM; the Fiji main window stays hidden. Never `System.exit`: use `Bootstrap.exit`
  (close images, bounded `context.dispose()`, `Runtime.halt`).
- Each document is a real IJ1 `ImagePlus` with a `HostCanvas` (`canEnlarge()==null`) inside a hidden `ImageWindow` with
  `setLayout(null)`; the canvas is re-parented into the workspace. Viewport order: drawing size, source rect,
  magnification, bounds. Never call `zoomOut`/`unzoom` on the canvas. Focus follows `Engine.focus(id)` (which calls
  `WindowManager.setCurrentWindow`), never clicks.
- All mutations go through `Engine.submit` and run on the engine's single worker thread, never on the EDT. The UI must
  not mutate pixels through `Engine.imagePlus(id)`.
- Typed commands run as `IJ.run(imp, exactLabel, completeOptions)`. Success is decided by postconditions and the Guard
  (error text, exception windows, modal dialogs), not by `IJ.run` returning.
- IJ1 singletons (ROI Manager, Results, Log) are resolved on every use, never cached. Images IJ1 opens behind the
  engine's back are adopted synchronously before any native command runs (adoption lock). Images carrying
  `HostCanvas.TRANSIENT_PROPERTY` are never adopted.
- Result-affecting globals (`blackBackground`, measurements, precision, conversions) are captured and shown, never set
  silently. `black` on a single-image Convert to Mask is an explicit AC5 global change.
- History is authoritative; macros are generated from it. Speech and the local NL interpreter never execute anything
  without a user confirmation; Penny's bridge applies the same `ConfirmationPolicy` to its plans
  ([FIDELIS-PROTOCOL.md](FIDELIS-PROTOCOL.md), "Plans and confirmation").
- Native interactions are *observed* (`CommandListener`, `RoiListener`, digests) and recorded with provenance `NATIVE`;
  typed actions are `TYPED`; original dialogs are `LEGACY_DIALOG`; the rest `UNRECORDABLE`.

## 2. Contract reference

### 2.1 Identifiers

| Thing | Form | Example | Notes |
|---|---|---|---|
| Document | `DocumentId(String value)` | `doc-3` | engine-assigned, session-scoped; `DocumentInfo.imagePlusId` is the IJ1 id (negative) |
| Command | `commandId` | `ij1:Process>Filters>Gaussian Blur...` | `ij1:` + IJ1 menu path + exact label; `CommandSchema.label` is passed to `IJ.run` |
| Operation | `ActionRequest.Operations.*` | `SET_AUTO_THRESHOLD` | DIRECT and SESSION kinds |
| Request | `requestId` | UUID | client-generated by the factory methods |
| Running operation | `operationId` | `op-12` | engine-assigned; used by `cancel` and events |
| History step | `actionId` | `act-7` | monotonic |
| Transcript | `transcriptRef` | speech transcript id or Penny task id | reserved request key, stripped from options, stored in `HistoryRecord.transcriptRef` |
| Parent step | `parentActionId` | `act-5` | reserved request key; child steps observed inside a CODE action |

Other reserved request keys (opt-in, additive): `expectedHistorySize` (the history size when the request was submitted;
the engine refuses with PRECONDITION_FAILED / subcode `STATE_CHANGED` if anything else entered the history first) and
`expectedRoi` (the `sc.fidelis.engine.RoiSignature` of the target's active selection, checked on the EDT when the
worker starts the step). Both are listed in `Options.RESERVED`; requests without them behave as before.

### 2.2 Requests (`ActionRequest`)

`record ActionRequest(String requestId, Origin origin, ActionKind kind, String commandId, String operation, Map<String,Object> params, TargetScope target, String confirmationToken, String replayOf)`

Factories: `command(origin, commandId, params, target)`, `direct(origin, operation, params, target)`,
`session(origin, operation, params, target)`, `code(origin, language, text, target, confirmationToken)`,
`withConfirmation(token)`.

- `COMMAND`: `params` must contain **every** key of the command's `CommandSchema` (booleans explicit). The engine rejects
  missing keys before running (VALIDATION_FAILED). Catalogue entries without a complete schema run through the legacy
  route (their original Fiji dialog, if any; reserved keys are ignored there).
- `DIRECT`/`SESSION` operations: SESSION `OPEN(path)`, `SAVE_AS(path, format)`, `CLOSE(discard)`,
  `NEW_IMAGE(title, type, width, height, slices, fill[, channels, frames])`; DIRECT `SET_ROI(roi)`, `CLEAR_ROI`,
  `ROI_LIST_ADD[(fromDocument, replace)]`, `ROI_LIST_SELECT(index)`, `ROI_LIST_DELETE(index)`,
  `ROI_LIST_RENAME(index, name)`, `SET_DISPLAY_RANGE(min, max[, channel])`, `SET_POSITION(channel, slice, frame)`,
  `SET_THRESHOLD(lower, upper)`, `SET_AUTO_THRESHOLD(method, dark)`, `RESET_THRESHOLD`, `UNDO`, `REDO`. Threshold and
  display operations apply an explicit `TargetScope` plane.
- `CODE`: `params.text`, `params.language`; requires a capability confirmation token (the first submit returns
  AWAITING_CONFIRMATION with a token).
- `TargetScope(DocumentId document, Integer channel, Integer slice, Integer frame, boolean allPlanes, Integer roiIndex)`;
  `of(doc)`, `wholeStack(doc)`, `withRoi(index)` (`-1` = active selection). Typed actions never rely on IJ1's implicit
  current image.
- `Origin`: `MENU, SEARCH, SHORTCUT, CANVAS, PANEL, NL_TYPED, NL_SPOKEN, MACRO, REPLAY, OBSERVED`.

### 2.3 Results and errors (`ActionResult`)

`record ActionResult(String operationId, OperationState state, EngineError error, StateDigest digest, HistoryRecord record, String confirmationToken, long durationMs)`; `succeeded()` means COMPLETED.

- `OperationState`: `QUEUED, VALIDATING, AWAITING_CONFIRMATION, RUNNING, WAITING_FOR_DIALOG, COMPLETED, FAILED, CANCELLED, ROLLED_BACK, PARTIAL`.
- `EngineError(ErrorCode code, String message, String subcode, Map<String,String> context, boolean recoverable, List<String> suggestions)`.
  Codes: `ENGINE_NOT_READY, UNKNOWN_COMMAND, VALIDATION_FAILED, PRECONDITION_FAILED, CONFIRMATION_REQUIRED,
  CAPABILITY_CONFIRMATION_REQUIRED, DIALOG_PENDING, EXECUTION_FAILED, POSTCONDITION_FAILED, CANCELLED, PARTIAL_RESULT,
  TIMEOUT, ENGINE_LOST, SNAPSHOT_BUDGET_EXCEEDED, IO_ERROR, UNSUPPORTED_IN_MODE`. Subcode `NOT_RUN` means a
  CommandListener vetoed the command; `STATE_CHANGED` means a reserved-key precondition failed.
- No-op rule: unchanged pixels are **not** a failure; an identity completes with a `no-op: ...` note in
  `HistoryRecord.errorSummary` and keeps no undo snapshot. A COMPLETED result therefore does not imply that pixels
  changed: read `digest.changed[].pixelsChanged`.
- After a failure or cancellation the engine rolls back to the pre-action snapshot when one exists (ROLLED_BACK).
- `StateDigest(added, removed, changed[DocumentChange(id, pixelsChanged, typeChanged, displayChanged, roiChanged, dimensionsChanged)], resultsRowsAdded, globalsDelta, newLogLines, windowsOpened, windowsClosed)`.

### 2.4 Engine facade (`Engine`)

Lifecycle `state()`, `addListener`, `removeListener`, `quit(discardUnsaved)`. Actions `submit`, `cancel(operationId)`.
Documents `documents()`, `document(id)`, `open(path)`, `focused()`, `focus(id)`, `imagePlus(id)` (hosting only),
`hostWindow(id)`. ROIs/results `rois(id)`, `activeRoi(id)`, `results()` (mirrors the IJ1 table; a `clear` rebuilds it),
`resultColumns()`. Catalogue `catalogue()` (about 950 entries), `schema(id)` (53 complete schemas), `search(query, limit)`
(weak on long clauses: also scan `catalogue()`). History `history()`, `exportMacro()`, `globals()` (keys such as
`blackBackground`, `measurements`, `precision`), `undoBudget()`.

Implementation-only (not in the interface; usable by tests and the bridge): `DefaultEngine.exportMacroSince(int)`,
`DefaultEngine.create(ImageJ)`, `Engines.current()`, `HostCanvas.TRANSIENT_PROPERTY`.

### 2.5 Events (`EngineEvent`, sealed)

Delivered on the EDT in sequence order; listeners must not block. Per operation: `OperationStateChanged(RUNNING)` before
any `OperationProgress`, before the terminal `OperationStateChanged`, before `StateDigestEvent`, before `HistoryAppended`.
Others: `EngineStateChanged`, `DialogPending`, `DocumentsChanged`, `DocumentFocusChanged`, `LegacyWindowChanged`
(declared; the engine does not emit it yet, the UI tracks windows itself), `ResultsChanged(totalRows)`, `LogLine`.

### 2.6 Data records

- `DocumentInfo(id, title, imagePlusId, width, height, nChannels, nSlices, nFrames, type, bitDepth, unit, pixelWidth, pixelHeight, sourcePath, sourceSha256, changed, virtualStack)`; pixel data is never exposed.
- `CommandSchema(commandId, label, menuPath, parameters, schemaComplete, headlessOk, consequence, preconditions, postconditionFamily, createsNewImage, hiddenGlobals)` with `ParameterSchema(key, type, defaultValue, choices, min, max, consequential, unit, defaultIsRemembered, visibleWhen, help, source)` and `Summary(commandId, label, menuPath, shortcut, framework, compatCategory, notes)`. `ConsequenceClass`: `AC0_READ_ONLY` ... `AC7_CODE`. The static schema source is `docs/data/commands.csv` plus `docs/data/commands-core-parameters.csv`, copied into the jar by `fidelis-app/tools/build.py`.
- `RoiGeometry` (float vertices, IJ1 conventions), `MeasurementRow` (full-precision doubles keyed by column, with document and action attribution), `MeasurementRow.Columns(headings, precision)`.
- `HistoryRecord(actionId, time, origin, provenance, commandId, label, params, target, macroLines, macroExact, globalsBefore, globalsDelta, outcome, errorSummary, transcriptRef)`; `Provenance`: `NATIVE, TYPED, LEGACY_DIALOG, UNRECORDABLE`.

### 2.7 Language and speech

- `NlService.interpret(String text, Origin origin, DocumentId focused) -> Proposal(Status status, String normalisedText, List<ActionRequest> requests, List<String> menuPaths, List<String> macroPreview, List<Map<String,String>> slotProvenance, List<String> questions, String refusalReason)`; `Status`: `READY, NEEDS_CLARIFICATION, REFUSED`. Never executes. `DefaultNlService` is deterministic: no code is generated from language.
- `DefaultNlService.confirmation(Proposal) -> ConfirmationPolicy.Decision(boolean required, boolean explicit, List<String> reasons)`; `DefaultNlService.vocabularyPrompt(List<String> titles)` (at most `VOCABULARY_MAX_CHARS = 560`); `VoiceToProposal.Result(proposal, transcriptRef, transcriptText, lowConfidence, ...)` with `confirmation()`, `requiresConfirmation()`, `requiresExplicitConfirmation()`, `proposalWithTranscriptRef()`.
- `SpeechService`: `state()` (`UNAVAILABLE, STARTING, READY, RECORDING, TRANSCRIBING`), `unavailableReason()`, `addListener/removeListener(Listener{stateChanged, level(rms)})`, `startRecording()`, `stopRecording() -> CompletableFuture<Transcript>`, `transcribeFile(Path)`, `setVocabularyPrompt(String)`; `Transcript(id, text, speechDetected, durationSeconds, segments, model, promptUsed, latencyMs)`. `WhisperSpeechService` runs `speech/server.py` (faster-whisper, hash-pinned `tiny.en`) as a child process; audio never leaves the machine. Penny's live voice is a separate route (`sc.fidelis.penny.voice`, [INTEGRATION.md](INTEGRATION.md) "Voice in the workspace").
- Confirmation semantics: `required` for every spoken proposal and typed AC2+; `explicit` for AC4+, CODE, a `black` parameter, an unfilled consequential slot, or not READY. The UI must not submit until Confirm; explicit cases need a separate deliberate act (not the default button, not a spoken "yes"). The value-aware constructor `ConfirmationPolicy(engine::schema, engine::globals)` used by Penny's bridge treats a `black` equal to the current BlackBackground global as not a change.

### 2.8 Service wiring

`Bootstrap` registers the product engine with `sc.fidelis.ui.EngineProvider.register(...)` and starts Penny's bridge
when a bridge token is found; `Workspace.launch` builds `DefaultNlService(engine)` and `WhisperSpeechService`, registers
them in `ServiceRegistry`, and registers the workspace's `PennyUi`. Tests use `sc.fidelis.testkit.ProductEngine.get()`
(one `DefaultEngine` per test JVM, registered with `EngineProvider`).

### 2.9 Threading and lifecycle

- Engine methods are callable from any thread; mutations run in submission order on one worker. Never block the EDT on a
  future; complete UI work in `whenComplete` + `SwingUtilities.invokeLater`.
- The speech worker is a child Python process; construct `WhisperSpeechService` off the EDT; close it on quit
  (process-tree kill).
- One Fidelis JVM per checkout at a time; always `--isolated-home` for `run.py`; `test.py` isolates `user.home` itself.

## 3. Changing the contract

Keep changes additive: new default methods, new operation constants, new optional or reserved parameters. State the
default behaviour for the existing implementers (`StubEngine`, `FakeEngine`, `HarnessSelfCheckEngine`) and the macro lines
a new operation records. Never introduce a second definition of an existing concept (a parallel request type, a UI-side
command id scheme, a second history model). Run `python3 -I fidelis-app/tools/build.py` and the full
`python3 -I fidelis-app/tools/test.py` before and after; a change in scientific behaviour needs parity evidence against
`verification/baselines` (pixels, ROI vertices, Results doubles, globals), never visual similarity.

## 4. Toolchain

No Maven or Gradle: the build uses the JDK bundled with the pinned Fiji (`FIDELIS_FIJI_DIR`, or `.local/fiji/Fiji.app`
installed by `python3 script/setup-fiji.py`; `fidelis-app/tools/fijienv.py` resolves it and reproduces Fiji's own JVM
flags).

```
python3 -I fidelis-app/tools/fetch_junit.py        # once per clone: pinned JUnit console runner (SHA-256 checked)
python3 -I fidelis-app/tools/build.py              # javac -> build/classes, build/test-classes, build/fidelis-app.jar
python3 -I fidelis-app/tools/run.py --smoke --isolated-home   # engine self-test: one real Fiji command verified, exit 0
python3 -I fidelis-app/tools/run.py --isolated-home            # launch the workstation (without Penny)
./script/run-fidelis.sh                                        # launch it with Penny's bridge and gateway profile
python3 -I fidelis-app/tools/test.py [--select-class FQCN ...] [--timeout SEC]   # JUnit 5 in one live Fiji JVM
```

The commands are the same on Windows (`python -I`, Fiji at `FIDELIS_FIJI_DIR`) and macOS (Apple silicon). Never modify
the Fiji installation, the Windows registry or system-wide Java settings.

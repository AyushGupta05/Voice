# Probes: agent G8 (P80–P87)

All probes were run on 2026-10-17 on Windows 11 Home 10.0.26200 (Intel Core Ultra 9 285H, 16 logical processors, 33,752,936,448 bytes RAM, Intel Arc 140T GPU). They ran against the pinned Fiji at `C:\Users\arnav\Documents\dev\Fiji` (Fiji 2.18.1-SNAPSHOT, `IJ.getFullVersion()` = `1.54p99`, Zulu JDK 21.0.7) in **GUI mode (not headless)**. Every probe is a Groovy script started by the launcher driver `P85-gui-driver.ps1`. Each `.out.txt` ends with the driver log, which gives the PID, launch time and exit.

**Exact command** (the driver runs it from cwd `C:\Users\arnav\Documents\dev\Fiji` through `Start-Process -PassThru` and kills only that PID if the hard timeout expires):
`fiji-windows-x64.exe -Dimagej.updater.disableAutocheck=true -Dg8.out.dir=<scratch run dir> --java-home=C:\Users\arnav\Documents\dev\Fiji\java\win64\zulu21.42.19-ca-jdk21.0.7-win_x64 --allow-multiple --run "<abs path to P8x script>"`
I invoked the driver as `powershell -NoProfile -ExecutionPolicy Bypass -File P85-gui-driver.ps1 -Script <abs .groovy> -OutDir <scratch>\G8\run<nn> -TimeoutSec <s> -GraceSec 10`.

**Termination.** `System.exit(0)` in GUI mode **blocked indefinitely** (P85 runs 1–2; see `P85-run2-jstack.txt`). The blocking chain was the shutdown hook `org.scijava.Context` dispose → `LegacyUI.dispose` → `IJ1Helper.dispose` → `ij.ImageJ.run` → `Window.dispose` → `EventQueue.invokeAndWait`. By the time it blocked, `ImageJ.run()` had already called `Prefs.savePreferences()`. That created `%USERPROFILE%\.imagej\IJ_Prefs.txt`, which G4's P52 had recorded as absent. From P85 run 3 onwards, every probe sets `changes=false` on its images and calls `Runtime.getRuntime().halt(0)`. This skips the shutdown hooks, so no preferences are saved and no "save changes?" dialog appears. At the end of the session I deleted the `IJ_Prefs.txt` and the empty `.imagej` folder that my runs had created (last write 08:42:58, nothing later). This restores the state G4 documented. I did not check the SciJava Java Preferences in the registry, which G4 saw being written during GUI runs.

**Pin check.** I ran it after the session at 2026-10-17T09:12:21+01:00 with `./.venv/Scripts/python.exe -c "from fidelis.adapters.fiji import verify_runtime; ..."`. It returned `f66953972bb5ed85b8ab0273e4294af5b03136c28c9ef617e24556bca523bafa`, which **matches** the pin. Nothing was written into the Fiji directory.

Known defects in the probe evidence:
- **P86 line `U6b`** compares against a reference image built from a different random seed, so it is meaningless. Use the CRC values in U4/U5 instead: `d058e36a` is the inverted state of A. They show that after Invert followed by Gaussian, a single `Undo.undo()` restores the post-Invert state, so Undo has only one level.
- **P83 D1** reads `pixel(10,10)` on a horizontal ramp. A Gaussian blur leaves a linear ramp unchanged, so this pixel cannot show whether the blur was applied. That the OK button applied the entered value is shown instead by `wasOKed=true` and by P81 (d), where the Recorder logged `sigma=3.5`.
